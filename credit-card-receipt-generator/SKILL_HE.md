# מחולל קבלות לתשלומי אשראי

## מטרה

הפק קבלות טיוטה ותיעוד התאמה מנתוני סליקת אשראי אמיתיים בישראל. קבל נתוני Cardcom, Tranzila, Grow/Meshulam או Pelecard, נרמל שדות תשלום, חשב הצגת מע"מ ישראלית, והפק Markdown, HTML או JSON למסירה להנהלת חשבונות.

השתמש רק בעסקאות אמיתיות. קבלה שהופקה כאן אינה הוכחת תשלום עצמאית ללא מזהה עסקה מהשער, מספר אישור, התאמה לדוח הסליקה ותיעוד במערכת הנהלת החשבונות. עבור חשבונית מס, בדוק מספר הקצאה של רשות המסים כאשר העסקה עוברת את סף B2B העדכני.

## ברירות מחדל בישראל

- מטבע: ILS / ₪.
- שיעור מע"מ רגיל: 18% לעסקאות חייבות במע"מ החל מ-01-01-2025.
- תקרת עוסק פטור לשנת 2026: ₪122,833 מחזור שנתי.
- סף מספר הקצאה בחשבוניות ישראל: ₪10,000 לפני מע"מ מ-01-01-2026, ולאחר מכן ₪5,000 לפני מע"מ מ-01-06-2026.
- פורמט תאריך ללקוח בישראל: DD-MM-YYYY.

## דוגמאות מעשיות

### דוגמה 1: קבלה מתוצאת Cardcom

```bash
python scripts/credit_card_receipt_generator_cli.py from-json cardcom-result.json \
  --gateway cardcom \
  --business-name "סטודיו כנרת" \
  --business-tax-id 515123453 \
  --format markdown \
  --output receipt.md
```

קובץ הקלט יכול לכלול `ResponseCode`, `TranzactionId`, `ApprovalNumber`, `DocumentNumber`, `DocumentUrl`, `Amount`, `Last4` ו-`CardBrand`. הלקוח דוחה מספר כרטיס מלא שעובר בדיקת Luhn.

### דוגמה 2: קבלת עוסק פטור

```bash
python scripts/credit_card_receipt_generator_cli.py sample --gateway grow --exempt-dealer
```

השתמש במצב זה לעוסק פטור. אל תציג מע"מ שנגבה. השאר את סכום הברוטו כסכום הקבלה והצג מספר עוסק.

### דוגמה 3: הפקת JSON להנהלת חשבונות

```bash
python scripts/credit_card_receipt_generator_cli.py from-json pelecard.json \
  --gateway pelecard \
  --business-name "קליניקת צפון" \
  --business-tax-id 012345674 \
  --format json \
  --output receipt.json
```

שמור את פלט ה-JSON ליד יצוא שער הסליקה. השתמש ב-hash של ה-payload המקורי לצורכי התאמה ובקרה.

### דוגמה 4: הצגת נתיב API של ספק

```bash
python scripts/credit_card_receipt_generator_cli.py endpoint tranzila payment_request
```

השתמש בנתיבי API לתכנון אינטגרציה בלבד. שלח בקשות חיות רק משרת מאובטח עם הרשאות הסוחר.

## דגשי יישום

- התייחס להצלחת שער הסליקה כתנאי הכרחי בלבד. התאם סכום, מטבע, מזהה עסקה ודוח סליקה לפני סגירת הנהלת חשבונות.
- שמור הרשאות שער סליקה מחוץ לקבצים שנוצרים.
- שמור רק מספר כרטיס מוסווה או טוקן שער. אל תשמור CVV.
- הפק קבלות ללקוח בעברית או באנגלית לפי תהליך העסק.
- השתמש בכתובת מסמך מהשער רק כאשר הספק הפיק מסמך חשבונאי רשמי.
- הוסף מספר הקצאה לרשומת חשבונית מס כאשר הסף מחייב זאת.

## טעויות שיש להימנע מהן

- אל תיצור קבלה עבור תשלום שלא בוצע.
- אל תשנה סכומים, תאריכים, מספרי אישור או מזהי עסקה כדי להתאים לסיפור רצוי.
- אל תציג PAN מלא, CVV, נתוני פס מגנטי או טוקן מלא בפלט.
- אל תסמן טיוטה כחשבונית מס רשמית אם מערכת הנהלת החשבונות או שער הסליקה לא הנפיקו אותה.
- אל תפצל עסקת B2B למסמכים קטנים כדי לעקוף סף מספר הקצאה.
- אל תתייחס לתגובת HTTP 200 כהצלחה בלי לבדוק את קוד התגובה של השער.
- אל תסתפק בצילום מסך כאשר ניתן לקבל יצוא מקורי משער הסליקה.

## רשימת בדיקה למסירה

1. אמת הצלחת שער סליקה ומזהה עסקה.
2. התאם סכום ומטבע לדוח סליקה או דוח תשלומים.
3. ודא מספר עוסק ושם לקוח.
4. בחר מצב מע"מ: רגיל או עוסק פטור.
5. בדוק סף מספר הקצאה לחשבונית מס B2B.
6. הפק טיוטת קבלה.
7. שמור JSON ו-hash מקור לביקורת.
8. שלח ללקוח רק מסמך סופי שאושר.
