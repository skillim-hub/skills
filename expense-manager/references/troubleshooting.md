# Troubleshooting

## Classification problems

### All rows are uncategorized

Cause: vendor and description fields are missing, generic, or mapped to the wrong columns.

Fix:

1. Confirm headers use recognized names such as `date`, `vendor`, `amount`, `description`.
2. Add meaningful descriptions: `internet`, `software`, `fuel`, `accountant`, `advertising`.
3. Keep Hebrew terms where they appear in the original data.
4. Add custom rule logic only after improving the source file.

### A restaurant expense is 0%

Cause: domestic hospitality is matched by conservative rule.

Fix:

1. Confirm whether the guest is an Israeli client or foreign guest.
2. For foreign guests, add description such as `foreign guest from Germany` or `אורח חוץ`.
3. Attach guest identity, country, and business purpose.
4. Keep accountant approval before changing treatment.

### Home office is 0%

Cause: the row matched `home_office`, but `home_office_percent` is not configured.

Fix:

```bash
python scripts/expense-manager-cli.py classify input.csv output.csv --home-office-percent 12.5
```

Keep the area calculation with source documents.

### Laptop is not immediately deductible

Cause: amount exceeds the immediate-expense threshold and asset keywords matched.

Fix:

1. Add the item to the asset register.
2. Confirm depreciation period with the accountant.
3. Use a small-equipment note only when the amount is below the threshold and policy allows immediate expense.

### Phone or vehicle VAT looks lower than expected

Cause: mixed-use VAT default applies.

Fix:

1. Confirm actual vehicle or phone use.
2. Adjust `vehicle_business_vat_rate` in the client when a different documented rate applies.
3. Keep accountant approval for final VAT reporting.

## File and encoding problems

### Hebrew appears as question marks or gibberish

Cause: spreadsheet tool opened UTF-8 incorrectly.

Fix:

1. Use output files generated by the helper, which include UTF-8 BOM for CSV.
2. Import into Excel through Data > From Text/CSV and select UTF-8.
3. Avoid saving back to legacy encodings.

### CSV fails with missing date/vendor/amount

Cause: headers are not recognized.

Fix:

Recognized header examples:

| Logical field | Accepted examples |
|---|---|
| date | `date`, `transaction_date`, `תאריך`, `תאריך עסקה` |
| vendor | `vendor`, `supplier`, `merchant`, `ספק`, `בית עסק` |
| amount | `amount`, `total`, `debit`, `סכום`, `סה״כ` |
| description | `description`, `details`, `memo`, `תיאור`, `פרטים` |

### Amount parsing fails

Cause: unsupported amount format.

Fix:

Use `₪1,234.50`, `1234.50`, `117`, or `(117)`. Remove extra words from the amount column.

### Dates fail to parse

Cause: unsupported format.

Fix:

Use `DD/MM/YYYY`, `YYYY-MM-DD`, `DD/MM/YYYY`, `YYYY/MM/DD`, or `DD.MM.YYYY`.

## VAT and tax logic problems

### Osek Patur shows VAT recovery

Cause: entity type was not set correctly.

Fix:

```bash
--entity-type osek_patur
```

Then confirm summary field `total_reclaimable_vat_ils` equals `0.00`.

### Foreign SaaS has VAT recovery

Cause: helper assumes VAT is included when `amount_includes_vat=True` and category is business-only.

Fix:

1. Confirm whether the document is an Israeli tax invoice.
2. If it is a foreign invoice without Israeli VAT, set VAT recovery to zero in accountant adjustments.
3. Keep the invoice and card charge together.

### Deductible amount seems lower than gross

Cause: recoverable VAT is removed from the income-tax base before applying the deduction rate.

Fix:

Review these fields in order: `amount_ils`, `reclaimable_vat_ils`, `income_tax_base_ils`, `deductible_rate`, `deductible_amount_ils`.

## Export package problems

### ZIP was created but source invoices are missing

Cause: package includes only source files passed to the export function. PDF/image invoices must be supplied separately or copied into the source folder before zipping.

Fix:

1. Store invoices in a controlled folder.
2. Add them to the accountant package manually or extend `source_files`.
3. Keep a separate invoice index when there are many PDFs.

### Accountant import rejects the CSV

Cause: target bookkeeping software expects different field names, date format, or debit/credit layout.

Fix:

1. Open `exports/import-mapping.json`.
2. Map fields to the target template.
3. Import into a test environment first.
4. Compare totals after import.

### Manifest hash mismatch

Cause: a file changed after ZIP creation.

Fix:

1. Regenerate the package.
2. Do not edit files inside the package after manifest creation.
3. If edits are required, rerun export and deliver the new ZIP.
