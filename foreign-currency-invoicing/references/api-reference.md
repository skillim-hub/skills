# API and Regulation Reference

This reference lists external sources, request patterns, response shapes, and implementation error handling for Israeli foreign-currency invoicing workflows. Validate live rules before production use.

## Source inventory

| Area | Source | Use in workflow | Verification status |
|---|---|---|---|
| Standard VAT rate | Israel Tax Authority VAT pages and Knesset/Finance publications | Determine the standard VAT rate by tax event date | Double-confirmed in `verification-log.md` |
| Representative exchange rates | Bank of Israel exchange-rate page, current public API, and SDMX series API | Fetch rate by currency and date | Double-confirmed in `verification-log.md` |
| Zero-rate and exemption distinction | Israel Tax Authority guidance and professional tax summaries | Avoid treating all foreign-currency invoices as zero-rated | Double-confirmed in `verification-log.md` |
| Bookkeeping and Israel Invoices | Israel Tax Authority bookkeeping and Israel Invoices publications | Maintain sequential documents and allocation-number evidence when required | Referenced as operational guardrail |

## Bank of Israel endpoint strategy

Use two endpoint families for different jobs.

### Date-specific representative rate for invoicing

Prefer the SDMX series endpoint for a specific invoice date or fallback search:

```text
https://edge.boi.gov.il/FusionEdgeServer/sdmx/v2/data/dataflow/BOI.STATISTICS/EXR/1.0
```

Request pattern:

```http
GET /FusionEdgeServer/sdmx/v2/data/dataflow/BOI.STATISTICS/EXR/1.0/RER_USD_ILS?startPeriod=2026-06-02&endPeriod=2026-06-02&format=csv HTTP/1.1
Host: edge.boi.gov.il
Accept: text/csv
```

Parameters:

| Parameter | Required | Example | Meaning |
|---|---:|---|---|
| `RER_USD_ILS` | yes | `RER_EUR_ILS` | Representative exchange-rate series code |
| `startPeriod` | yes | `2026-06-02` | First date to return |
| `endPeriod` | yes | `2026-06-02` | Last date to return |
| `format` | recommended | `csv` | CSV output for stable parsing |

Generated by the client:

```python
from foreign_currency_invoicing_client import build_boi_rate_url

url = build_boi_rate_url("USD", "02/06/2026")
```

### Current-day public API

Use the public API for current-day display or manual verification, not as the primary historical endpoint:

```text
https://boi.org.il/PublicApi/GetExchangeRates
https://boi.org.il/PublicApi/GetExchangeRate?key=USD
https://boi.org.il/PublicApi/GetExchangeRates?asXml=true
```

The public API is documented by Bank of Israel QA material and by the official exchange-rate extraction guide as the current JSON/XML feed.

## Expected CSV shape

```csv
TIME_PERIOD,OBS_VALUE,SERIES_CODE,BASE_CURRENCY,COUNTER_CURRENCY
2026-06-02,3.7000,RER_USD_ILS,USD,ILS
```

The parser accepts common SDMX field names such as `TIME_PERIOD`, `OBS_VALUE`, `SERIES_CODE`, `BASE_CURRENCY`, and `COUNTER_CURRENCY`.

## Expected JSON shapes

Single-rate current API shape:

```json
{
  "key": "USD",
  "currentExchangeRate": "3.7000",
  "unit": 1,
  "lastUpdate": "2026-06-02"
}
```

Nested-list shape:

```json
{
  "exchangeRates": [
    {
      "currencyCode": "EUR",
      "rate": "4.0200",
      "unit": "1",
      "date": "02/06/2026"
    }
  ]
}
```

The parser accepts `key`, `currency`, `currencyCode`, `CurrencyCode`, and `CURRENCYCODE` for the currency field. It accepts `currentExchangeRate`, `exchangeRate`, `rate`, and `RATE` for the rate field. It accepts `unit`, `unitOfCurrency`, `Unit`, and `UNIT` for the quoted unit.

## Expected XML shape

```xml
<CURRENCIES>
  <CURRENCY>
    <CURRENCYCODE>USD</CURRENCYCODE>
    <RATE>3.7000</RATE>
    <UNIT>1</UNIT>
    <LAST_UPDATE>02/06/2026</LAST_UPDATE>
  </CURRENCY>
</CURRENCIES>
```

## Response-to-calculation mapping

| Response field | Client field | Accounting use |
|---|---|---|
| Currency code or series code | `ExchangeRate.currency` | Match invoice currency |
| Rate value | `ExchangeRate.rate` | Quoted NIS amount for the unit |
| Unit | `ExchangeRate.unit` | Divide rate by unit to get NIS per one currency unit |
| Date | `ExchangeRate.date` | Prove rate was valid for the issue date or prior publication date |
| Source | `ExchangeRate.source` | Audit trail label |

## Error table

| Error | Cause | Handling |
|---|---|---|
| Empty response | API returned no body or local fixture is empty | Retry once, then try previous published date |
| Invalid JSON, XML, or CSV | API gateway message, HTML page, or corrupt file | Store payload for diagnosis and retry later |
| Currency not found | Unsupported currency or unexpected response shape | Check currency code and Bank of Israel support |
| Missing rate | Response lacks a numeric rate value | Reject calculation and obtain a valid rate source |
| Date after issue date | Later publication was used for earlier invoice | Reject and fetch same-day or prior published rate |
| Network timeout | Connectivity or endpoint downtime | Retry with backoff; do not invent a rate |

## VAT reference rules for implementation

- Use standard VAT for regular taxable Israeli supplies.
- Use the standard rate applicable on the tax event date. The helper defaults to 18% from 01/01/2025 and 17% before that date.
- Use zero-rate only when the transaction qualifies and evidence is retained.
- Treat exempt and zero-rate as distinct classifications. Exempt revenue and zero-rated revenue are not interchangeable.
- For foreign-resident services, evaluate statutory exceptions and actual use of the service. Do not rely on currency or customer address alone.
- Record VAT in NIS even when the commercial price is in foreign currency.

## Request examples with the CLI

Build a date-specific rate URL:

```bash
foreign-currency-invoicing rate-url --env sandbox --currency USD --as-of-date 02/06/2026
```

Parse a saved Bank of Israel payload:

```bash
foreign-currency-invoicing parse-rate --env sandbox --currency USD fixtures/boi-usd.csv
```

Create an invoice with a manual rate:

```bash
foreign-currency-invoicing create \
  --env sandbox \
  --currency EUR \
  --issue-date 02/06/2026 \
  --exchange-rate 4.02 \
  --lines-json '[{"description":"Implementation","quantity":"1","unit_price":"2500","vat_category":"standard"}]'
```

## Data retention

Save these items together:

- Final invoice PDF or accounting-system export.
- JSON calculation output.
- Bank of Israel URL and response payload or equivalent export.
- Customer evidence for non-standard VAT categories.
- Contract, purchase order, delivery proof, and payment record.
- Professional approval for unusual classification or alternative rate source.
