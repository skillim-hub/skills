# אינטגרציית חשבשבת

## מטרה

חברו נתוני חשבשבת לתהליכי הנהלת חשבונות ישראליים בצורה בטוחה: ייבוא וייצוא נתונים, סנכרון לקוחות וספקים, שליפת פקודות יומן, יצירת קובץ BTKN עקבי לסביבת ביניים, הכנת בדיקות OPENFORMAT/BKMV, ובדיקת חובת מספר הקצאה לפני שליחת נתוני חשבונית לשע"ם או למערכת הנהלת חשבונות מחוברת.

העדיפו יצוא רשמי וממשקי API של הספק לפני פענוח קבצים ישנים. התייחסו לקבצי רוחב קבוע ישנים כקלטי הסבה בלבד לאחר אישור מנהל חשבונות, רואה חשבון או תמיכת הספק.

## כללי עבודה עדכניים בישראל

| נושא | כלל אינטגרציה עדכני |
|---|---|
| מע"מ | השתמשו ב-18% לעסקאות בישראל החל מ-01-01-2025. שמרו את השיעור בקובץ תצורה ולא בקוד מפוזר. |
| תקרת עוסק פטור | השתמשו ב-₪122,833 כתקרת מחזור שנתית לשנת 2026. |
| מספר הקצאה לחשבוניות ישראל | לחשבוניות מס B2B הכוללות מע"מ, הפעילו תהליך מספר הקצאה כאשר הסכום לפני מע"מ גבוה מ-₪10,000 החל מ-01-01-2026 ומ-₪5,000 החל מ-01-06-2026. |
| יצוא רשמי לביקורת | העדיפו OPENFORMAT/BKMV, בדרך כלל `INI.TXT` ו-`BKMVDATA.TXT`, למסירה לרואה חשבון או לרשות המסים. |
| API של חשבשבת בענן | השתמשו באסימון הרשאה ובתיעוד WizCloud API כאשר קיימת אינטגרציה דו-כיוונית. |
| ייבוא ותיק | השתמשו בקבצי ממשק מתועדים כגון `HESHIN.DAT`, `BANKIN.DAT`, ו-`IMOVEIN.DOC` יחד עם קבצי `.PRM` מתאימים. |

## תהליך מומלץ

1. זהו את הקשר החברה: ח.פ או מספר עוסק, שנת מס, שיעור מע"מ, מטבע, גרסת חשבשבת, וחיבור ענן או ייצוא מקומי.
2. העדיפו API לסנכרון שוטף של לקוחות, ספקים ומסמכים. השתמשו בקבצים להסבה, סגירת חודש או אתר ללא חיבור.
3. אמתו שכל מספר לקוח או ספק ישראלי מכיל 9 ספרות לפני שימוש בהתאמה או במספר הקצאה.
4. שמרו תצורה נפרדת לכל חברה. אל תשתפו אסימונים, תיקיות יבוא, טווחי מספור או ברירות מחדל של פקודות יומן.
5. העלו קבצים לסביבת ביניים ב-UTF-8. המירו יצוא Windows-1255 פעם אחת בלבד ושמרו עותק מקור.
6. התאימו סכומים לפני יבוא: חובה שווה זכות, מע"מ שווה סכום נטו כפול שיעור מע"מ, ברוטו שווה נטו ועוד מע"מ, וספירת רשומות תואמת לסיכום.
7. בדקו חובת מספר הקצאה לפני מסירת חשבונית מס B2B מעל הסף.
8. השאירו דיווחים רשמיים והחלטות חשבונאיות בתהליך אישור של מנהל חשבונות או רואה חשבון.

## דוגמאות מעשיות

### חישוב מע"מ ובדיקת סף הקצאה

```bash
python scripts/hashavshevet_integration_cli.py vat 12000 --date 2026-01-15 --customer-vat 514087337
```

התוצאה מציגה נטו, מע"מ, ברוטו, סף פעיל, והאם נדרש תהליך מספר הקצאה.

### המרת יצוא לקוחות בעברית ל-JSON

```bash
python scripts/hashavshevet_integration_cli.py csv-to-json customers_windows1255.csv customers.json
```

השתמשו לאחר פתיחת קובץ יצוא שמציג עברית משובשת בעורך UTF-8.

### יצירת קובץ BTKN

קלט JSON:

```json
[
  {
    "company_id": "514087337",
    "entry_id": "JE-1001",
    "entry_date": "05-06-2026",
    "debit_account": "1100",
    "credit_account": "4000",
    "net_amount": "1000.00",
    "vat_amount": "180.00",
    "reference": "INV-1001",
    "allocation_number": "123456789",
    "description": "יבוא חשבונית מס"
  }
]
```

פקודה:

```bash
python scripts/hashavshevet_integration_cli.py generate-btkn entries.json BTKN.TXT
```

התייחסו לקובץ BTKN כחבילת ביניים עקבית. אשרו כל פורמט יבוא ייצור מול סביבת חשבשבת הרלוונטית.

### סנכרון לקוח דרך לקוח typed

```python
from scripts.hashavshevet_integration_client import (
    CustomerSupplier,
    HashavshevetIntegrationClient,
)

client = HashavshevetIntegrationClient(
    "https://api.example.local",
    token="TOKEN_FROM_HASHAVSHEVET_ADMIN",
)

result = client.sync_customer_supplier(
    CustomerSupplier(
        account_id="C100",
        name="לקוח ישראל בעמ",
        vat_number="514087337",
        email="finance@example.co.il",
    )
)
```

### שליפת פקודות יומן להתאמה

```python
client.pull_journal_entries(
    company_id="514087337",
    from_date="2026-01-01",
    to_date="2026-01-31",
)
```

הריצו בדיקת חובה וזכות לפני העברת הנתונים לספר אחר.

### בדיקת חשבונית לפני שליחת הקצאה

```bash
python scripts/hashavshevet_integration_cli.py validate-invoice invoice.json
```

שדות חובה מינימליים: `company_id`, `invoice_number`, `invoice_date`, `customer_vat_number`, ו-`net_amount`.

## תבנית רב-חברתית

השתמשו במבנה תיקיות צפוי:

```text
companies/
  514087337/
    config.json
    raw/
    staging/
    outgoing/
    archive/
  515555555/
    config.json
    raw/
    staging/
    outgoing/
    archive/
```

הגדירו לכל חברה:

| הגדרה | שימוש |
|---|---|
| `company_id` | ח.פ או מספר עוסק המשמש לאימות ושמות יצוא. |
| `base_url` | כתובת API של סביבת העבודה. |
| `token_secret_name` | מפתח בכספת סודות לאסימון החברה. |
| `vat_rate` | שיעור מע"מ נוכחי, בדרך כלל `0.18`. |
| `default_income_account` | כרטיס הכנסה ברירת מחדל רק לאחר אישור. |
| `default_vat_output_account` | כרטיס מע"מ עסקאות לחשבוניות מכירה. |
| `import_folder` | תיקיית קליטה ייעודית לחברה. |

## פתרון תקלות

| סימפטום | סיבה סבירה | פעולה |
|---|---|---|
| עברית מוצגת כסימני שאלה או ג'יבריש | יצוא Windows-1255 נפתח כ-UTF-8 | קראו עם `read_text_auto` או הריצו `convert-encoding`. |
| חובה וזכות לא שווים | חסרה שורת מע"מ, עיגול שגוי או יבוא חלקי | חשבו מע"מ מחדש, עגלו לשתי ספרות ודחו פקודה לא מאוזנת. |
| חסר מספר הקצאה | חשבונית מעל הסף או חסר מספר עוסק של לקוח | בדקו סף ושלחו בתהליך שע"ם המאושר. |
| חשבשבת דוחה יבוא מסמך | חסר כרטיס, כמות אפס או מסמך משולב שאינו נתמך | בדקו את כללי הייבוא המתועדים ופצלו מסמכים בעת הצורך. |
| נוצרו לקוחות כפולים | מזהי כרטיס לא עקביים או מספרי עוסק לא מנורמלים | נרמלו מספרי עוסק והשתמשו במזהה חיצוני קבוע. |
| נתונים נקלטו לחברה שגויה | אסימון משותף, תיקייה משותפת או כתובת API שגויה | הפרידו תצורה לפי חברה וחסמו עיבוד כאשר ח.פ אינו תואם. |

## דפוסים לא רצויים

- פענוח ישיר של בסיס נתונים קנייני כאשר קיים יצוא רשמי או API.
- שימוש במיפויי רוחב קבוע משוערים כפורמט מחייב.
- ערבוב חברות באותה תיקיית יבוא.
- יבוא חשבוניות מס B2B מעל הסף ללא טיפול במספר הקצאה.
- שמירת אסימוני API בקוד, Markdown, צילומי מסך או קבצי דוגמה.
- המרת טקסט עברי כמה פעמים ודריסת המקור.
- פתיחת כרטיסים אוטומטית ללא דוח חריגים.
- חישוב מע"מ היסטורי לפי שיעור נוכחי בלי לבדוק תאריך חשבונית.
- שימוש בכרטיס מעבר יחיד לכל שגיאת מיפוי.
- העברת פקודות יומן שאינן מאוזנות בדיוק לשתי ספרות.

## רשימת בדיקה לפני ייצור

- ח.פ החברה תואם לחברת היעד.
- כל קובצי המקור נשמרים בארכיון ללא שינוי.
- קידוד הקובץ ידוע ומומר פעם אחת.
- ספירת הרשומות תואמת לסיכומי המקור.
- פקודות היומן מאוזנות.
- סכום מע"מ וברוטו תואמים לכללים.
- חובת מספר הקצאה נבדקת לפי תאריך חשבונית.
- מזהי לקוחות וספקים עקביים.
- לוג dry-run אינו כולל רשומות שנדחו.
- אישור מנהל חשבונות או רואה חשבון נשמר לשינויי מיפוי.
