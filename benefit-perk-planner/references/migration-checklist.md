# Migration Checklist

Use this checklist when moving from informal perks to a documented benefit program.

## Use when

Recurring reimbursements lack written policy, benefits differ without criteria, payroll uses manual adjustments, provider invoices do not reconcile to HR data, contractors receive employee-style perks, managers approve exceptions in chat, the business is moving to a meal-card provider/payroll-coded wallet/HR platform, or a freelancer is separating personal and business expenses.

## Phase 1: inventory

- [ ] List recurring benefits.
- [ ] Identify recipients.
- [ ] Identify payment route.
- [ ] Capture monthly and annual cost.
- [ ] Collect receipts and invoices.
- [ ] Identify informal promises.
- [ ] Identify excluded groups.
- [ ] Identify contractor participation.
- [ ] Identify vendor data.

## Phase 2: risk classification

| Risk | Red flag | Action |
|---|---|---|
| Payroll | recurring payment not coded | payroll review |
| Tax | assumed tax-free | tax verification |
| VAT | missing invoice | accounting review |
| Labor | verbal promise | policy and agreement review |
| Equity | unclear eligibility | transparent criteria |
| Privacy | excessive personal data | minimize data |
| Contractor | contractor gets employee perks | classification review |
| Budget | no caps | set caps |

## Phase 3: policy design

- [ ] Define purpose.
- [ ] Define eligible population.
- [ ] Define caps.
- [ ] Define pro-rata rules.
- [ ] Define remote-work rules.
- [ ] Define leave, reserve duty, parental leave, unpaid leave, and termination treatment.
- [ ] Define required documents.
- [ ] Define approval owner.
- [ ] Define payroll component.
- [ ] Define accounting documents.
- [ ] Define exception process.
- [ ] Define review date.

## Phase 4: grandfathering

| Option | Use when | Risk |
|---|---|---|
| No grandfathering | old process is risky | dissatisfaction |
| Temporary grandfathering | transition time needed | admin complexity |
| Permanent grandfathering | contractual promise exists | inequity and cost |
| Buyout | benefit must end but value is material | payroll/tax review |

## Phase 5: provider migration

- [ ] Request sandbox or demo.
- [ ] Confirm data fields.
- [ ] Confirm employee file format.
- [ ] Confirm invoice format.
- [ ] Confirm utilization export.
- [ ] Confirm API or CSV.
- [ ] Confirm fees.
- [ ] Confirm cancellation and data deletion.
- [ ] Pilot with a small group.
- [ ] Freeze old reimbursements after cutover.

## Phase 6: payroll and accounting migration

- [ ] Create payroll components.
- [ ] Map expense accounts.
- [ ] Confirm VAT handling.
- [ ] Define reconciliation owner.
- [ ] Test payroll import.
- [ ] Test journal entry.
- [ ] Store approvals and invoices.
- [ ] Confirm first payroll.

## Phase 7: communication

Include effective date in DD/MM/YYYY for Hebrew communications, eligible population, what changed, caps, how to use the benefit, what happens to old reimbursements, support contact, privacy notice if personal data is processed, and a statement that treatment follows applicable law and payroll configuration.

## Phase 8: review

After 30 days, compare expected and actual cost, check failed transactions, payroll errors, invoice reconciliation, and employee questions. After 90 days, measure utilization, compare vendors, revisit eligibility, decide whether to expand/reduce/replace, and publish policy update.
